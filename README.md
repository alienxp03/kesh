# kesh

Kesh is a Kitty workspace manager for finding projects, composing single- and
multi-repository development sessions, creating branch worktrees, saving
layouts, switching between sessions, and working with Claude, Codex, and pi
agents.

It is designed for a keyboard-driven daily workflow: open a project, choose a
layout, create an isolated worktree when needed, and return to the same work
without rebuilding your terminal state.

## Quick start

### Install

#### Homebrew

```sh
brew install alienxp03/tap/kesh
brew upgrade kesh
```

#### From source

Install the binary where Kitty expects it:

```sh
go build -o ~/.local/bin/kesh ./cmd/kesh
```

Or build a development binary without installing it:

```sh
go build -o "${TMPDIR:-/tmp}/kesh-dev" ./cmd/kesh
```

### Configure Kitty

Kesh uses Kitty remote control. Add these required settings to `kitty.conf`:

```conf
allow_remote_control yes
listen_on unix:/tmp/kitty

map cmd+shift+o launch --type=overlay ~/.local/bin/kesh
map cmd+shift+p launch --type=tab      ~/.local/bin/kesh agents
```

Reload Kitty after changing its configuration. The first mapping opens the
main picker; the second opens the Agents view.

### Start using kesh

```sh
kesh
```

Kesh works without a project configuration. Run this inside a project when you
want a starter recipe:

```sh
kesh init
```

This creates `.kesh.yaml`. The file is optional and can describe pane layouts,
multiple repositories, and setup for newly created worktrees.

## What kesh manages

Kesh brings several Kitty and development concepts into one picker:

- **Projects** — repositories discovered from Kitty sessions, zoxide, and saved
  state.
- **Sessions** — Kitty layouts that contain one or more tabs.
- **Tabs and windows** — the hierarchy inside an open Kitty session.
- **Workspaces** — configured repository entries in `.kesh.yaml`; a project can
  contain one workspace or several repositories.
- **Worktrees** — isolated Git checkouts for branch work, with optional setup
  files, environment changes, port randomization, and hooks.
- **Saved sessions** — Kitty layouts that can be restored after they are
  closed.
- **Pins** — native Kitty session shortcuts generated by kesh.
- **Agents** — active Claude, Codex, and pi terminal windows with live previews.

A green row means the entry is currently open. Saved or closed entries keep the
same identity and can be restored later.

## Daily workflows

### Open or focus a project

Run `kesh`, select a project, and press `enter`. Kesh focuses the existing Kitty
session when one is open, or opens the configured layout when it is closed.

Use `l` and `h` to move between sessions, tabs, and windows. The detail panel
shows information relevant to the selected row, including paths, commands,
worktrees, pull requests, and agent state.

### Work on several repositories together

Select multiple projects with `space`, then press `n` to name and create a
multi-project session. Each selected project becomes a tab while remaining
available as its own project entry for future sessions.

For a repeatable multi-repository layout, define one workspace per repository
in `.kesh.yaml` and open the full hierarchy with `kesh`.

### Create an isolated branch worktree

Press `w` to open the Worktrees surface, then `n` to create a worktree. Choose
the branch in the UI. Kesh creates the checkout, applies configured worktree
setup, and opens the layout.

Worktree setup runs only when a fresh worktree is created. Opening the current
repository, or reopening an existing worktree, does not run `post_create`
hooks, copy/symlink setup, port randomization, or `set_env` mutations.

### Resume saved work

Press `s` on a selected entry to save its tabs, splits, and working directories.
Use `S` when foreground commands should also be captured and rerun on restore.
Saved entries remain available after their Kitty session is closed.

Press `enter` on a closed saved entry to restore it. Press `x` then `y` on a
closed saved entry to remove its saved snapshot.

### Work with pull requests

Press `C` on a project to check out a GitHub pull request. Kesh accepts a PR
URL, `owner/repo#123`, or a bare number when a project is selected. Checking out
the same PR again focuses its existing worktree.

In Worktrees, `o` or `g` opens the exact matching pull request in the browser.
PR status is cached and refreshed in the background. Kesh warns when the local
branch no longer matches the PR head.

### Switch to an agent

Run `kesh agents` or use the Kitty Agents mapping. The Agents view lists active
Claude, Codex, and pi windows ordered by recent focus. Press `enter` to focus an
agent and `p` to toggle its live terminal preview.

## Project configuration

A project recipe lives in `.kesh.yaml` at the project root. The main concepts
are:

- `workspaces[].panes` defines the layout and commands used when opening a
  workspace.
- `workspaces[].worktree` defines setup for a fresh worktree belonging to that
  workspace.
- Top-level `worktree.dir` and `worktree.defaults` apply globally to newly
  created worktrees.

Here is a complete example:

```yaml
# Optional shared worktree setup for all newly created worktrees.
worktree:
  dir: ~/workspace/worktrees
  defaults:
    files:
      copy:
        - .env

workspaces:
  - name: api
    repo: ./api
    panes:
      - commands:
          - nvim
        focus: true
      - commands:
          - pnpm run dev
        split: horizontal
      - split: horizontal # interactive shell
    worktree:
      files:
        symlink:
          - .tool-versions
      hooks:
        post_create:
          - pnpm install
      randomize_ports:
        - file: .env.local
          vars:
            - PORT
      set_env:
        - file: .env.local
          vars:
            API_URL: "http://localhost:${api:.env.local:PORT}/api"

  - name: web
    repo: ./web
    panes:
      - commands:
          - nvim
        focus: true
      - commands:
          - pnpm run dev
        split: horizontal
```

### Layouts

Use `panes` for commands that belong to the daily launch layout. Multiple
values in one pane's `commands` list run sequentially. A pane with only
`split` opens an interactive shell.

```yaml
panes:
  - commands:
      - nvim
    focus: true
  - split: horizontal
  - commands:
      - pnpm run dev
    split: vertical
```

`split: vertical` splits the pane immediately before it. Nested layouts may
require Kitty's `tall` layout; see [Kitty integration](#kitty-integration).

### Worktree setup

Use `worktree.hooks.post_create` for one-time bootstrap work such as installing
dependencies. Do not put long-running development servers in hooks; put those
in `panes`.

`files.copy` and `files.symlink` are applied to fresh worktrees. Global files in
`worktree.defaults.files` are combined with workspace-specific files.

`randomize_ports` changes selected variables in a setup file for each fresh
worktree. `set_env` writes derived values into the selected file.

A reference such as:

```yaml
API_URL: "http://localhost:${api:.env.local:PORT}/api"
```

reads `PORT` from the `api` workspace's `.env.local`. The first component must
match a workspace `name`; the optional middle component is the source file.

## Kitty integration

### Optional Kitty mappings

Kesh generates native Kitty action aliases for pins. Include the generated file
before defining mappings:

```conf
include ~/.local/state/kesh/kitty-pins.conf

map cmd+0 kesh_pin_0
map cmd+1 kesh_pin_1
map cmd+2 kesh_pin_2
map cmd+3 kesh_pin_3
map cmd+4 kesh_pin_4
map cmd+5 kesh_pin_5
map cmd+6 kesh_pin_6
map cmd+7 kesh_pin_7
map cmd+8 kesh_pin_8
map cmd+9 kesh_pin_9
```

Useful optional settings:

```conf
tab_bar_filter session:~
map cmd+p goto_session -1

map --when-focus-on title:project-picker ctrl+j
map --when-focus-on title:project-picker ctrl+k
map --when-focus-on title:kesh ctrl+j
map --when-focus-on title:kesh ctrl+k
```

If a layout contains nested splits, keep Kitty's `tall` layout enabled:

```conf
enabled_layouts splits:split_axis=horizontal,tall,stack
```

If `tall` is unavailable, `Cmd+R` can fall back to `splits` and flatten the
layout.

### Pin lifecycle

Pins are stored for the current Kitty run. Kesh generates `kesh_pin_0` through
`kesh_pin_9` aliases and reloads Kitty when they change. On a confirmed normal
quit, kesh clears pins and generated mappings. If Kitty is force-terminated,
the next run detects the stale process and clears them.

## Keyboard reference

The picker starts in normal mode. Arrow keys work anywhere rows are selectable.

| Key | Action |
|---|---|
| `j` `k`, `ctrl+j` `ctrl+k` | Move selection |
| `enter` | Open, focus, or restore the selected entry |
| `l` / `h` | Descend into or return from session → tabs → windows |
| `e` | Expand or collapse a selected session or tab |
| `/` | Fuzzy-filter |
| `tab` / `shift+tab` | Change the active filter |
| `space` | Select a project or SSH host for a multi-project session |
| `n` | Name and create a session from selected items |
| `c` | Clone a Git repository |
| `C` | Check out a GitHub pull request |
| `s` | Save tabs, splits, and directories |
| `S` | Save and capture foreground commands |
| `p` then `0`–`9` | Pin the session to a slot |
| `p` then `x` | Unpin the session |
| `r` | Rename a session, tab, or window |
| `w` | Open Worktrees |
| `o` | Open the selected worktree's exact PR |
| `D` then `y` | Destroy an entry; in Worktrees, destroy worktree and branch |
| `X` then `y` | Remove merged worktrees |
| `x` then `y` | Close a session, tab, or window; remove a worktree in Worktrees |
| `q` | Quit |

Press `enter` or `esc` to leave filter mode and return to command mode.

### Worktrees

Open with `w` and close with `esc`. Rows are ordered by branch and pull-request
state: default branch, open PR, merged PR, closed PR, then entries without a
matching PR.

| Key | Action |
|---|---|
| `n` | Create a worktree and branch |
| `enter` | Open or focus a worktree |
| `r` | Fetch and refresh status |
| `p` | Pull |
| `g` | Open the exact PR |
| `x` then `y` | Remove the worktree |
| `D` then `y` | Remove the worktree and branch |
| `X` then `y` | Remove worktrees merged by Git ancestry or matching PR |
| `space` | Enable bulk pull or removal |

`X` revalidates merged status instead of relying only on the cache.

### Agents

The Agents view is a flat list of active Claude, Codex, and pi windows.

| Key | Action |
|---|---|
| `enter` | Focus the agent window |
| `p` | Toggle the live terminal preview |
| `/` | Search agent, project, tab, command, and directory fields |

## Advanced features

### Projects, zoxide, and SSH

Kesh discovers projects from Kitty sessions, saved state, and zoxide. Zoxide
integration is automatic and silent when available. SSH locations are shown as
separate entries and can participate in multi-project sessions.

### Cloning repositories

Press `c` to open the clone form. Enter a Git URL and destination; `tab` moves
between fields and `enter` starts the clone. After cloning, kesh adds the
repository to zoxide when available and opens the workspace.

### Saved sessions

Saved entries are stored in the kesh state directory. A normal save captures
Kitty tabs, splits, and working directories without attempting to capture a
foreground process. `S` explicitly includes detected foreground commands so
Kitty can rerun them when restoring.

Saved entries remain after their sessions close. Closed saved snapshots can be
restored with `enter` or deleted with `x` then `y`.

### Pull-request status

For Git checkouts, branch and pull-request information loads lazily when a row
is focused. Cached status appears immediately; Worktrees refreshes status in
the background and throttles repository refreshes to once per minute.

Status colors are:

- Green — open PR
- Purple — merged PR
- Red — closed without merging

These lifecycle colors apply when the local branch and PR head commit match.
Kesh warns when they do not.

### Global configuration

Global configuration is stored at:

```text
${XDG_CONFIG_HOME:-~/.config}/kesh/config.yaml
```

The current global path settings are:

```yaml
clone:
  root: ~/workspace

worktree:
  root: ~/workspace/worktrees

checkout:
  root: ~/workspace
```

Project recipes live separately in `.kesh.yaml`. Global configuration controls
where repositories and worktrees are found or created; project configuration
controls layouts and fresh-worktree setup.

Kesh stores runtime state under XDG state and cache directories, including pins,
saved sessions, session snapshots, and pull-request status cache.

## CLI reference

```text
kesh                         Open the full hierarchy
kesh init                    Create .kesh.yaml in the current directory
kesh ssh                     Show SSH hosts
kesh saved                   Show saved sessions
kesh agents                  Show active agents
kesh switch SLOT             Focus a pinned Kitty session (SLOT 0–9)
kesh clear-pins              Clear pins for the current Kitty run
kesh clear-pins --on-quit    Clear pins when Kitty quits
```

## Troubleshooting

### Kesh cannot connect to Kitty

Check that Kitty has both settings enabled:

```conf
allow_remote_control yes
listen_on unix:/tmp/kitty
```

Also verify that the mapping and the installed binary point to the same kesh
executable.

### Nested panes are flattened

Enable Kitty's `tall` layout:

```conf
enabled_layouts splits:split_axis=horizontal,tall,stack
```

### Pins remain after a crash

Kesh clears stale pins when it detects that the Kitty process recorded for the
previous run is no longer alive. You can also run:

```sh
kesh clear-pins
```

### A worktree cannot be removed

Kesh may refuse removal when the worktree is dirty, locked, current, or has a
branch that still needs confirmation. Use `D` for explicit destruction, or
resolve the Git state and retry.
